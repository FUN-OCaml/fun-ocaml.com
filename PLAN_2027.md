## Goal

1. **Archive** the 2025 (Warsaw) edition in place, mirroring how the 2024 (Berlin) edition is already archived.
2. **Repurpose the landing homepage** (`output/index.html`) to launch the 2027 (Bengaluru) edition, scaffolding a new year-scoped module set so future 2027 content (speakers, schedule, sponsors) can drop in without touching prior years.

The site is a static generator: each edition is isolated under `data/{year}/` + `templates/{year}/`, stitched together in `src/main.ml`. The 2024 archive is the reference implementation for everything below.

## Reference: how the 2024 archive works today

- `data/2024/` (data2024.ml, people.yml, sessions.yml, schedule/, media/) is untouched and still compiled.
- `templates/2024/` (layout, home, session, avatar, social_icons) is untouched and still compiled.
- `src/main.ml` renders `Templates2024.Home.make()` to `output/2024/index.html` and each 2024 session to `output/2024/{slug}/index.html`.
- `output/index.html` (the live homepage) renders `Templates2025.Home.make()` — this is the line that "points" the homepage at the current edition.
- The 2025 footer (`templates/2025/layout.mlx`) links out to `FUN OCaml 2024` at `/2024/`.
- `Makefile` `assets` target copies `data/2024/media/*` → `output/2024/` and `data/2025/media/*` → `output/2025/`.

We will follow this exact pattern for 2025→2027.
